    设计决策（相对现网的变更点）

  • 筛选收进单行检索条：手机号精确查询 + 回复时间 + 处置筛选 seg + 查询，与号码搜索、统计报表同一语言；隐私说明沉为条底细字，独立筛选卡片取消。前端
  • 状态列全角色可见：「已加黑 / —」从处置列拆出，viewer/approver 也能看到加黑结果（响应本已返回 blacklisted，纯显隐变化）；处置按钮仍仅 operator/admin。现有
  • 关联批次可点击：跳转 /batches 对应批次详情 Drawer 上下文，与号码搜索页同一动线；未关联保留琥珀 tag 并附一行小字说明原因。前端
  • 总数沉入结果底栏：移除页头右侧「当前结果」计数块，底栏「共 N 条 · 每页 20」与分页器同行。前端
  • 处置筛选 seg（可选扩展）：全部 / 待加黑退订 / 已加黑。「已加黑」过滤走 blacklist_hmac_alias EXISTS，成本低；「待加黑退订」需 ingest 时在 reply_event 增加 is_optout 布尔列（在打码后内容上判定，不涉明文号码，手写迁移 + openapi 回填）。评审不过则整项砍掉，行内 verm 高亮已能支撑人工识别。契约+库表
  • 加黑确认如实告知留痕：对话框文案明确「加入后发送将自动剔除该号码；加黑行为与操作人将写入审计日志」，成功 toast 同步提示已记审计。现有
  • 移动端：保留卡片流，实现时与桌面合并为单一数据源组件，消除现网双份渲染；空态维持两行规约（一行结论 + 一行出路）。现有

    契约核对

  • 列表字段全部来自 POST /api/v1/web/replies 现有响应（id / phone 掩码 / content / batch_no / reply_time / blacklisted，分页固定 20）；不新增解密端点、不新增导出（PRD FR-07）。现有
  • 状态列全角色可见仅改变前端显隐，响应字段不变；处置按钮角色门槛不变（operator/admin）。现有
  • 批次跳转为纯前端路由（/batches + Drawer 上下文），无契约变更。前端
  • 处置筛选 seg 为扩展：blacklisted 过滤仅加查询参数；「待加黑退订」需 reply_event.is_optout 列（ingest 在打码后内容上判定，不含明文号码）。若采纳：迁移手写、schema.sql 注释同步、openapi.yaml 同 commit 回填（规则 17/25/35）。契约+库表
  • 审计沿用 reply_content_read（只记条数）与 reply_optout（@audited）；审计载荷不含号码列表（规则 21）。现有
  • 手机号全程掩码、无解密路径（规则 2）；查询参数走 POST body 不进访问日志（D072）；回复正文入库前已打码，界面不二次处理（规则 27）。现有
