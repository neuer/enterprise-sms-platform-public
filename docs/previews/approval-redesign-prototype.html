现状诊断（当前 ApprovalView）

  • 三套列表标记并存：pending 卡片流 / 已办桌面表格 / 已办移动列表，同一数据三条渲染路径，字段口径与 testid 各异，改一处要动三处加三份契约测试。
  • 没有队列语义：固定按提交时间倒序，expires_at 24h 过期即作废的单据不会上浮；剩余有效期在页面加载时算一次，停留期间不过期、不更新，临期单据被淹没即自动过期 + 配额占用。
  • 零筛选零搜索：仅状态 + 分页；仓储层预留的 dept 过滤未透出，无类别 / 申请人 / 时间维度；页大小写死 20。
  • 无待办感知：页面只 onMounted 加载一次，导航无角标；审批人只能靠仪表盘 KPI 跳转，进页后新单据不会自动出现。
  • 正文随列表整页解密：20 条 content 一次性解密返回、整页记一次敏感读审计——粒度粗，且与「详情按角色查看」的口径不一致。
  • 决策反馈靠猜：decision 端点返回空 200，前端用固定文案猜「进入队列 / 进入定时」；窗外营销被改派 scheduled 的真实去向用户看不到。
  • 决策输入流断裂：通过 / 驳回各弹一个 MessageBox.prompt，意见输入与单据上下文脱离；409 已被处理只有 toast。
