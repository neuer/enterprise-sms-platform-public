    设计决策（相对现网的变更点）

  • 结果区改词条墙：敏感词是短词，整行表格浪费横向空间；改为 auto-fill 卡片流密排（词面 + 删除 ×），添加时间收进悬停 tooltip（实现用 el-tooltip），每页 60（接口 size 上限 100 内取值）。移动端同一 DOM 自适应换行，不再维护表格 / 卡片双份渲染。前端
  • 删除 × 常驻弱化、悬停朱红：每词一个 ×（朱红hover），点击仍走二次确认；词面只做展示与删除，不做行点击抽屉（词条无更多事实可展开）。前端
  • 添加收进 440 抽屉：撤下现网顶部常驻的大输入卡，页头右侧「添加敏感词」主按钮唤起抽屉；textarea 前端实时预检（有效 / 批内去重 / 超长行号），与服务端同规则（trim、批内去重、单词 ≤64 字）；400 报错只带行号、不带词面内容，内联展示。前端
  • 命中策略改两态 seg：现网页头 el-select 改为「命中阻断 / 仅审计」seg，与全站胶囊语言一致；切换即写 sensitive_hit_action 配置，失败回退原值并提示。现有
  • 筛选收进单行检索条：关键词 220px + 查询 / 重置，与黑名单、上行回复同一语言；说明沉条底，独立筛选卡片取消。词库可能达数万条，保持服务端分页与过滤，不走「接口全量返回 · 前端过滤」。现有
  • 总数沉入底栏：页头不再放计数；底栏「共 N 条 · 每页 60」与分页器同行。前端
  • 删除确认如实告知后果与留痕：删除后该词不再参与命中判定（按当前策略阻断或仅审计，验证码 / 通知 / 营销全类别一致生效）；删除行为与操作人写入审计日志；toast「已删除敏感词 · 本次操作已记入审计」，成功后重查列表。现有
  • 添加结果如实分账：toast「新增 N 个 · 已存在跳过 M 个 · 本次操作已记入审计」，对应响应 added / skipped（词库已存在的词跳过不重复入库）。现有
  • 页头副文写明命中机制事实：命中按当前策略阻断（422 SENSITIVE_WORD）或仅审计，全类别一致执行；变更写库即重建 Aho-Corasick 快照，其余进程按修订号自动加载——管理员改词前即可预判生效面。现有

    契约核对

  • 全部数据来自现有 GET/POST/DELETE /api/v1/web/admin/sensitive-words（admin Bearer），字段 id / word / created_at；策略读写走现有 GET/PUT /admin/configs（sensitive_hit_action）；不新增端点、不新增字段、不加导出。现有
  • 每页 60 仅为前端 size 参数取值（服务端上限 100），无契约变更。现有
  • keyword 服务端 ILIKE 仅作用 word 且转义通配符。现有
  • 添加 trim + 批内去重 + 单词 ≤64 字；已存在词 ON CONFLICT DO NOTHING 跳过计入 skipped；超长 400 INVALID_PARAM 只带行号。现有
  • 审计 sensitive_word_add / sensitive_word_delete 记 {count}，不含词面列表；确认与 toast 文案如实告知。现有
  • 写库同事务推进 sys_config 修订号，管理端即时重建快照，其余进程下次匹配前按修订号自动重载——界面无额外表达，提交失败时展示结构化错误。现有
  • 页面 admin 专属（PRD 附录 A #12），viewer / operator / approver 无入口；路由守卫与导航维持现状。现有
