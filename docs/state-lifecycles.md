# 状态生命周期与恢复合同

这是状态 owner 和验收入口的导航，不是新的状态存储或执行引擎。产品状态与错误码仍以
[PRD](../PRD.md)、[工程约定](../AGENTS.md)、现有 SQL guard 和测试为准。
“隐式”表示状态由多个字段、时间或资源所有权共同决定，不表示存在缺陷。
维护时先定位 owner，再检查事件、guard、事务、副作用和恢复条件；不要仅按字段名称重写。

## 前端异步结果的归属

每次异步操作都绑定展示对象、请求代际与会话。关闭、对象替换、会话退役、卸载是不同事件，
需要分别失效。`catch`、`finally`、通知、事件发射和数据回写适用同一守卫。
取消等待不等于服务端写入回滚；服务端事实不能从 loading 或 HTTP 202 推断。

| owner | 事件与 guard | 效果与结束条件 | 恢复与验证 |
|---|---|---|---|
| `PhoneReveal` | active 且未退役才开始；快照 generation、recordKey、session origin | 仅当前操作可写展示、通知、发事件和结束 loading；hide/close/session-clear 同步清空；unmount 不可逆 | 新展示上下文可重新授权；同掩码不代表同对象；`phone-reveal-lifecycle`、`batch-phone-lifecycle` 测试 |
| `useAdminStepUp` | run 替换原 intent 并恰好结束旧 waiter；submit 要求 open/password/intent 且非 busy/disposed | closed/prompting/authorizing 仅从原 open/busy 派生；授权结果匹配原 generation；settle 只消费一次 | 当前错误允许重试；cancel/session-clear/dispose 清口令、废弃旧令牌；`admin-step-up`、`app-step-up-flow` 测试 |
| `useSendDraft` | 原 requestGeneration + draftRevision 判定受理响应归属；首次提交冻结 payload/biz_id | editing/submitting/accepted/response-unknown 是局部展示；业务拒绝与传输未知分开；摘要使用服务端 scheduled_at | 未知请求仅人工重试原快照，不自动换键；实质编辑仍是新意图，不撤销旧请求；`send-submission-snapshot` 测试 |
| `useSendPreview` / import | fingerprint 和 generation 共同限定预检；import 解析与已消费独立 | A→B→A 不能复活 A 的旧结果；已消费包不能因编辑恢复 ready 资格 | 新上传建立新导入事实；`send-preview-generation`、`send-draft-lifecycle` 测试 |
| `VendorTestConsole` | restore、poll、completion-refresh 各有 latest-read 通道；操作 ID 限定 owner | 202 仅开始跟踪；只有终态后完整权威刷新才解除未确认阻断；未知 status 仍阻断 | 有界轮询耗尽只停止查询，保留 ID；手动重连恢复原查询；新 owner 取消旧链；`vendor-test-console` 测试 |

这些状态留在组件易失内存。只有控制台恢复所需的 operation ID/type 延用已有会话存储合同，
没有密码、令牌、手机号或请求正文的新持久化。保留发送页的导入消费轴和预检新鲜度轴，
不将它们塞入一个总 status。幂等确认仍受服务端有效期和权威事实约束，不承诺永久重试资格。

## 后端协议与事务边界

| 协议 / owner | 事件、guard 与事务 | 副作用、终态与恢复 |
|---|---|---|
| B02 分片 / `send_repository_attempt`、`send_attempt` | claim 以状态、attempt generation/token 原子取得调用权；finalize 必须仍属原 claim；结果和后续 Outbox 同事务 | 调用前不可用或明确 safe reject 才允许下一候选；超时/断网为 uncertain，禁止重发或切厂商；旧 worker 放弃结果，不覆盖新状态 |
| B03 拆分 / `inflight_split` | 1006 确定拒绝后按同一 split generation 原子拆分；容量事实与父子状态同事务 | split_capacity_blocked 只等待本地容量恢复；不再次调用父分片；父子容量守恒，恢复入口是 reconcile |
| B08 幂等 / `idempotency` | scope/key 唯一；claim 租约、完成映射有效期、保护中的批次生命周期分轴；接管与 generation 推进受同一锁约束 | completed 映射是原受理结果；丢失或无法确认不能作为新请求；旧 owner 不能完成新 generation；只有可信退役证明后才可过期复用 |
| B09-B10 受理 / `pipeline`、`send_inflight` | 导入预留、claim、usage/inflight 预留归当前 owner；批次、绑定、claim 完成与 Outbox 在事务内转移所有权 | COMMIT 确认丢失先查权威事实；已 batch_bound 不补偿；证明未绑定且属于当前 owner 才精确释放；不能按异常类型猜测回滚 |
| B11 释放 / `usage_ledger` | reserved/committed/release_requested/released/uncertain 是不同事实；释放请求与稳定事件同事务，消费由唯一事件约束 | 重复消费或 ACK 丢失不能第二次回补；release_requested 可恢复；事务回滚不产生孤立可发送 Outbox |
| B12-B13 投影 / `usage_ledger_projection`、频控 alias | PG 为事实源；重建持有数据库锁与 Redis token；绝对值带版本，窗口由权威时钟决定；alias 不可逆归并 | marker 缺失、重建中、Redis 不可确认均失败关闭；旧版本/旧窗口不得覆盖新事实；重建重试写绝对值而非重复 INCR |
| B20 Outbox / `outbox_repository`、`outbox` | 发布租约和消费租约独立；claim、ACK、complete 均检查原 lease；队列/task/args 白名单与业务资格共同检查 | published 只是投递事实；丢 ACK 可重投，但副作用仍由业务 claim 防重；submitted/uncertain 不得重新外呼；跨队列恢复仍经 Outbox |
| A01/A03/A08/B19/B22 授权 | 在单次令牌消费、外呼和下载实际副作用点复核账号、会话、部门、应用配置版本；事务锁内再次检查到期 | done/旧 JWT/历史创建权不是永久授权；取消 UI 不返还已消费令牌；refresh grace 不延长 AD 完整认证期限；撤销和权威不可用失败关闭 |

资源恢复必须由现有仓储/服务入口执行。本表没有授予直接改 SQL、删除事实账本、运行清理、
真实短信、共享测试更新或生产部署的权限。发布、测试更新、备份与生命周期工具按 D122/D125 逐项评估、独立提交；不恢复已退役入口。
