# 保留的 Alpine 安全更新

基础镜像继续使用固定的多架构 index digest。该目录保留基础镜像之外必需的
Alpine 官方签名包，分别覆盖 x86_64 和 aarch64。构建根据基础层的实际架构选择，
核对 SHA256SUMS、验证基础层已有信任库中的签名，并在 BuildKit 禁网步骤安装。
安装不查询镜像站、不添加签名密钥、不允许未信任包。只读 bind mount 不进入最终层。

`manifest.json` 记录包名、版本、架构、上游仓库、许可证标识及取得日期。
包来源为 Alpine 官方 dl-cdn 镜像；Redis 7 使用 v3.21/main，其余使用 v3.24/main。
保留原始 APK 字节与其中的元数据，禁止解包重签或以其他架构包代替。

更新时，在目标固定 digest 的原生架构容器中查看仓库候选，取得精确版本并执行
`apk verify`，然后更新包、SHA256SUMS 和 manifest。每个组件两种架构必须同时验证。
若旧包被上游清理，已有 Git 提交仍保留构建输入；不得临时去掉版本约束继续发布。
基础 digest 升级后若已包含修复，应删除确已多余的覆盖包并重跑相同验收。

验收包括损坏/缺包失败关闭、两架构断网安装、真实最终镜像冷构建、核心四镜像
G2 与发布 Trivy/SBOM、同 SHA 独立重建。扫描必须覆盖最终应用依赖，不能以基础镜像
扫描代替。已保留的包不保证未来无漏洞；每日 CI 和发布门禁使用更新的漏洞数据库。
新增漏洞时重新执行上述更新流程，不使用忽略未修复漏洞或降低严重性阈值的方法通过。

mailer 由独立 Compose 部署，单独保留最终镜像扫描与 SHA 证据；核心发布 manifest、
离线索引和回退仍严格包含 api/web/postgres/redis 四个镜像。共享测试更新对未分类
部署资产继续失败关闭，本目录的存在不授权修改数据镜像或执行部署。
