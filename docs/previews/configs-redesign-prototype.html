    设计决策（相对现网的变更点）

  • 检索条单行化：旧 config-toolbar（340px 搜索框 + 右侧计数）改为方案 A 单行检索条——关键词 220px + 分组 seg（全部 / 运行调度 / 发送策略 / 安全控制 / 告警通知 / 生命周期，按实际出现的分组动态生成），点选即过滤；条底说明「接口全量返回 · 前端过滤」。不新增查询参数。前端
  • 调度生效规则由 warning alert 改为常驻规则条：与用户页用户名 / 密码规则条同一 slim 语言；第一格保留「BEAT RESTART 参数由 beat 与 API 在启动时读取，修改后需重启两个容器，不动态热更」（AGENTS #34 界面提示义务），第二格写敏感值规则（不回显、留空保持原值、清除即置空）。前端
  • 撤下页头「N 项受控运行参数」计数块：与全站「页头不放页级计数」口径一致；总数沉到保存栏左侧「共 N 项受控参数 · M 项待保存」，待保存数以琥珀色数据字呈现。前端
  • 参数区分组小节与卡片收紧：分组标题行改 panel-2 底 + mono 计数；.config-item 卡片、BEAT RESTART / SENSITIVE 徽章、范围提示、格式提示、重置默认值与最近更新行全部保留（既有 testid 不改名）。前端
  • beat 参数保存确认拆后果正文与审计细字：正文如实告知「保存后必须重启 beat 与 API 容器才会生效，运行中不热更」，审计细字写明逐键留痕；保存成功 toast 统一「系统参数已更新 · 本次操作已记入审计」。现有
  • 认证源面板化：本地源行与 AD 工作台脱离 el-card，结构与 testid 不变——「保存草稿 → 测试连接 → 启用配置」状态机、Bind Secret / CA 就绪 chips、编辑即失效旧测试资格、高级属性映射折叠、目录组角色映射全部保留；「禁用 AD」确认同样拆后果正文（登录页不再显示 AD、已登录会话不受影响、配置与映射保留）与审计细字。现有
  • 真实联调页签不动：VendorTestConsole 为独立受控组件，安全状态机界面已被可达性契约锁定，本次重构不触碰。现有
  • 行为与 testid 全量保留：config-search / config-<key> / config-reset-<key> / local-provider / ad-server / save-ad-draft / test-ad / activate-ad / disable-ad / mapping-* / save-role-mappings 与页签键盘左右切换均不变。前端

    契约核对

  • 参数清单 GET /api/v1/web/admin/configs 返回 ConfigItem[]（key / value / value_type / description / group / sensitive / configured / beat_restart_required / updated_by / updated_at / default / min_value / max_value）；分组 seg 由 group 字段前端聚合，关键词前端匹配 key / description / group，不新增查询参数。现有
  • 保存 PUT /admin/configs 体 {items:[{key,value}]}：非敏感项仅在值变化时提交，敏感项仅在显式编辑或清除时提交；beat 参数二次确认后提交；变更逐键写审计（config_update）。现有
  • 认证源 GET /admin/auth-providers/ad、PUT /draft、POST /test、POST /activate、POST /disable：草稿保存即递增 draft_version 并使旧测试资格失效；启用要求当前草稿 tested；bind 密码不录入、不回显（无 bind_password 字段）。现有
  • 角色映射 GET / PUT /admin/auth-providers/ad/role-mappings：全量替换语义，提交前 trim 并丢弃空组行。现有
  • 错误如实展示：409 PROVIDER_CONFIG_UNTESTED / PROVIDER_CONFIG_STALE、422 INVALID_PROVIDER_CONFIG、503 AUTH_PROVIDER_UNAVAILABLE 直接透出服务端 message，页面不另造文案。现有
  • 零契约变更：不新增端点与字段、不服务端化过滤、不动真实联调控制台；页签结构（运行参数 / 认证源 / 真实联调，viewer 无第三个）与路由守卫维持现状。现有
