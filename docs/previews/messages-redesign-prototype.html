    设计决策（相对现网的变更点）

  • 视图切换收进检索条：列表 / 时间线改为 seg 分段控件，与统计报表筛选条同一语言；页头不再放两个大按钮。前端
  • 号码徽标条两种视图常驻：检索成功后，黑名单状态（verm tag）+ 退订来源 + 近 30 日接收量（mono）固定在结果区顶部，FR-26 要求不再只在时间线可见。列表视图需 /web/messages 响应带回同一 badge 对象。契约
  • 授权查看提升到徽标条：精确搜索下号码恒定，解密从逐行眼睛改为徽标条一次操作一次审计；实现复用现有 POST /messages/{id}/phone/decrypt（取当前结果任一行 id；时间线视图先静默拉一页列表取 id），无契约变更；行内不再重复入口。现有
  • 列表去重列：移除恒定的「号码」列，时间合并为 mono 单行 + 批次号副行；类别竖条、verify 内容 OTP 等长打码（******）沿用既有规约；failed/unknown 内联厂商回报原文。现有
  • 时间线：日分组头（日期 + 星期 + 事件数）+ 1px 垂直细线 + 类别色圆点；下行左对齐带类别竖条，上行回复右缩进 24px、sink 底、前缀「↩ 用户回复」；truncated 时用琥珀提示条如实告知 500 条上限。现有
  • 类别/状态筛选收进结果区页脚：与分页同行，只服务当前列表，不再随视图切换显隐。前端
  • 空态两行规约：初始态讲「这里会出现什么」，无结果态讲「下一步怎么调」。现有

尚未查询号码记录 输入完整手机号后，这里会出现该号码跨批次的收发轨迹；切换到时间线可一屏还原「我们发了什么、用户回了什么」。
