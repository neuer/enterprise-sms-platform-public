为什么改

  • 现网分段控件是「模式开关」语义，认证源是「这次用哪套身份系统」。二者不是同一件事。
  • 配置页已经用 LOCAL / AD 标记 + 名称 + 一行说明。登录页应复用这套对象语言，而不是另做一种控件。
  • 说明写在选项内部，不再单独占一行提示，也不恢复 v2 的大卡片、assurance 徽章和审计脚注。
  • 仅一个认证源时，分段会剩下一枚孤钮；来源条可以收成只读确认，不假装还有得选。

变更（待评审）

  • 认证源由分段改为身份来源条：单选、左侧 verdi 细条、配置页同源标记。
  • 卡片从 352px 放宽到约 400px，给标记和说明留行宽；仍是单卡、无插画，接近 ui-design.md 的 430px 口径。
  • 无障碍建议：radiogroup / radio，比 aria-pressed 更贴单选。
  • 默认仍选中服务端返回的第一项。规则 31 的硬约束是「失败不回退」，不是「禁止预选」。
  • 备选 C 两步流不作为默认实现，除非评审认为「未选定前不出现凭据」更重要。

不动

  • 每次登录只提交一个 provider_code，失败不自动改走另一源。
  • 账号框占位仍区分「账号 / 企业 AD 账号」；展示名仍用服务端 name（本地账号 / AD 账号）。
  • 首次改密仍在同卡片内切换，短期令牌只留组件内存。
  • 错误内联，锁定 / 限流同一位置；不弹窗，不把审计当页脚文案。
  • 深色令牌、serif 品牌、verdi 主色；本期只交原型，不改 Vue 实现。
