    设计决策（相对现网的变更点）

  • 筛选收进方案 A 单行检索条：投递状态五枚 seg + 事件三枚 seg 点选即重查（直接映射现有 status / event 参数），应用保留可过滤下拉（动态清单，挂载时拉取、失败不阻塞列表），批次号 220px 模糊关键词走「查询」按钮；口径说明沉条底。filter-toolbar 紧凑工具栏与 el-card 外壳在本页退役，检索条并入 reply-* 共享组。前端
  • 重试序列迁入常驻规则条：原挤在筛选条尾部的「60s → 5m → 15m → 1h → 1h」改为检索条下常驻三格规则条——重试序列（以 callback_retry_schedule 为准、beat 启动时读取、不热更）、租约接管（停滞即租约超时未续约）、手动重推前提（仅 dead、应用启用、URL/密钥未变更）。规则条与 user-rules / config-rules 同组。前端
  • 账本表格瘦身、密集事实收进详情抽屉：表格保留 任务/应用、事件、批次/引用、状态（停滞 tag 并入状态列副行）、尝试/下次重试、最近结果、创建时间、操作 八列；关联 RID、事件 ID、租约与接管明细、完成时间移入 440px 详情抽屉（松散事实格），行操作新增「详情」。前端
  • dead 脉冲保留在页头：dead_total 为全库口径、不受筛选影响，与用户页撤下的「当前页摘要」不同，不构成翻页失真；底栏合并「共 N 项 · 每页 20 · dead 总计 M」，/ops 嵌入态页头隐藏时 dead 总计仍常驻可见。现有
  • 手动重推确认拆后果正文与审计细字：如实告知「重置为待投递并清零重试计数、按应用当前回调配置重新投递、应用停用或 URL/密钥变更将被拒绝」；审计细字写明重推行为、操作人与任务 id 留痕；toast 统一带「本次操作已记入审计」，成功后重查列表。现有
  • 空态两行规约双变体 + 错误条带重新加载：空库「启用应用回调后，投递任务会出现在这里」，筛选无结果引导「清除筛选」；加载失败 el-alert 内联重试。前端
  • 行为与既有 testid 保留：应用下拉 callback-app-filter、批次号 callback-batch-filter 不改名；新增 status/event seg、详情与重推 testid；loadToken 竞态守卫与重推在途防重不变；移动端 760px 表格↔卡片双渲染。前端

    契约核对

  • 列表 GET /api/v1/web/admin/callbacks 参数 status / app_id / event / batch_no / page / size，响应 CallbackPage{total, dead_total, items[]}；状态与事件 seg 直接映射现有枚举参数，批次号服务端 ILIKE（通配符已转义），不新增查询参数。现有
  • 重推 POST /{id}/retry：仅 dead 可重推，重置 pending 并清零 retry_count；应用停用、回调 URL / 密钥变更或配置吊销时 409 STATE_CONFLICT；@audited("callback_retry") 留痕操作人与任务 id。现有
  • 详情抽屉完全来自列表行投影（event_id / correlation_id / 租约 / 接管 / 时间戳均为现有字段），不新增详情端点；目标 URL、签名密钥与消息 body 不在响应模型内，本页无处展示。现有
  • dead_total 为全库 dead 计数、不受筛选影响（现有响应字段），页头脉冲与底栏「dead 总计」同源。现有
  • 零契约变更：不新增端点、不新增字段、不加导出；页面 admin 专属（PRD 附录 A），/callbacks 独立路由与 /ops?tab=callbacks 嵌入态共用同一组件，路由守卫与导航维持现状。现有
