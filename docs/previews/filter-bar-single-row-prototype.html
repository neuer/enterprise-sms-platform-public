现状诊断（依据 2026-08-20 真机截图与当前代码实测）

  • 内容区预算 ≈1200px：真机截图 2928px@2x（视口 1464 CSS px）− 侧栏 ≈220px − 内容内边距 ≈48px。
  • 批次列表筛选条需求 ≈1251px，超约 50px：批次号 179 + 类别 236 + 渠道 177 + 创建时间 355 + 更多筛选 84 + 查询/重置 132 + 间隙 60 + 内边距 28。动作按钮落到第二行右侧，第二行左大半为空白，纵向多花 ≈40px。
  • 审批中心筛选条需求 ≈1286px，超约 86px：状态 384 + 类别 150 + 部门 182 + 申请人 194 + 排序 150 + 刷新/30s 124 + 间隙 70 + 内边距 32。「刷新 · 30s 自动」整组落第二行。
  • 密度原型已预警：batch-density-prototype.html 指出「flex-wrap 折行 + 按钮 margin-left:auto 的组合在折行时仍会在行尾留白」，popover 修复落地后该问题显性化。

两个方案共用的瘦身清单（分歧点只在动作按钮位置）

  • 批次列表：创建时间 300→244px（内部 10.5px 等宽、分隔符收紧，显示到分 YYYY-MM-DD HH:mm，值仍为完整 ISO）；批次号 140→124px 并允许收缩到 96px 兜底（flex:0 1 124px，先挤输入框再折行）；分段钮 padding 11→9px。
  • 审批中心：部门 150→128px、申请人 150→112px（登录名为短字符串）；状态下拉与排序 118→112px；状态分段钮 padding 13→10px；「30s 自动」降为 9.5px 角注；条内边距 16→14px、gap 14→12px。
  • 移动端不变：≤760px 媒体查询维持现有折行/纵向堆叠，本原型只改 ≥1200px 桌面段。

单行达成 批次 ≈1150px（余 ≈50）、审批 ≈1173px（余 ≈27），1200px 预算内均单行 批次 bar ≈1119px、审批 bar ≈1104px，余量更宽松（≈80–100px），更耐未来加字段
交互变化 零变化：按钮位置、提交动线、刷新位置全部保持 批次查询/重置移到 chips 行，动线跨行（有「条件已变更」角标牵引）；审批刷新上移页头，与徽标同组
改动面 仅 workspace.css 宽度/内边距 + BatchView 批次号收缩；≈10 行 两页模板结构移动 + chips 行/页头样式 + 契约测试文本同步；≈40 行
风险 低：不动 DOM 结构，快照/契约测试基本不感知；审批页余量偏小（27px），状态计数为 3 位数时仍可能折行 中：chips 行承载按钮后变挤，「口径 ⓘ」弱化说明性；审批页头右侧元素增至 3 组
移动端 ≤760px 两方案一致：维持现有媒体查询折行堆叠，不做改动
