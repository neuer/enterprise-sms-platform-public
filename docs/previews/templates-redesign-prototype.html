    设计决策（相对现网的变更点）

  • 筛选条单行化：状态 seg（全部 / 待审核 / 已通过 / 已拒绝 / 草稿）带计数，与名称/内容关键词输入同行；两者均为全量列表响应的前端推导，不新增查询参数（接口无分页，不过滤时底栏仅「共 N 个模板」）。前端
  • 内容列即变量列：正文中 {n} 渲染为 verdi 描边变量片并角标最大长度（{1}≤8），独立「变量约束」列取消；标题下小字只保留平台编号。现有
  • 待审核细分双阶段：vendor_template_id 为空 → 副行「提交厂商中」（同步按钮不出现，避免空轮询）；已有编号 → 「厂商审核中 · #编号」+ 可手动同步。全部由现有字段推导。前端
  • 驳回原因上浮：已拒绝行状态列副行直接显示 vendor_reject_reason 摘要（现网藏在详情抽屉），修复动线少一步。现有
  • 详情抽屉加审核轨迹：已提交 → 已绑定厂商编号 → 审核结果 三段步骤条，驳回原因 verm 块置顶；附「厂商格式预览」（平台 {n} → 厂商 {s最大长度} 的确定性转换展示，唯一转换实现仍在服务端 services/template.py，前端只做预览）。前端
  • 编辑器变量自动识别：变量行随内容实时增删并保留已设 max_len，取消手动「从内容识别 / 添加变量」按钮；非法占位与断档编号内联报错；抽屉内嵌厂商格式实时预览；驳回后重交时顶部 verm 条展示上次驳回原因，按钮文案「重新提交审核」并如实告知将生成新厂商编号。前端
  • 已通过模板给出路：行操作「用于发送」跳 /send?template_id=N 预选该模板（SendView 读取 query，纯前端路由扩展，评审不过则砍掉）。前端扩展
  • 模板全局共享：operator/approver/admin 读取同一模板库，不渲染历史兼容的部门字段。前端
  • 删除确认如实告知：已通过或已被批次引用的模板不可删除（服务端 409 裁决，按钮显隐只是提示）；删除行为与操作人写入审计，toast 同步提示留痕。移动端合并为单一数据源卡片流。现有

    契约核对

  • 列表与详情字段全部来自 GET /api/v1/web/templates 现有响应（id / name / content / var_specs / dept / vendor_template_id / vendor_state / vendor_reject_reason）；dept 仅为历史兼容字段，界面不展示；接口无时间戳与创建人，界面一律不虚构。现有
  • 状态计数、关键词过滤、待审核双阶段、审核轨迹、厂商格式预览均为前端推导或确定性转换展示；{n}→{s最大长度} 唯一转换与校验实现仍在 services/template.py（规则 23），前端预览不另造转换逻辑、以同一函数语义为准。前端
  • 「用于发送」为纯前端路由扩展：/send?template_id=N，SendView 挂载时读取并预选，不新增接口、不改契约；评审不过则整项砍掉。前端扩展
  • 角色边界不变：读 operator/approver/admin、写 operator/admin；模板数据全局共享且不渲染部门列；写操作审计沿用 template_create/update/delete/sync，读取记 template_content_read 条数（规则 14/21）。现有
  • 状态机不变：create/update 直落 pending 并入 Outbox 绑定意图（realtime worker 持凭据执行 BindTemplate）；delete 受「已通过 / 已被 sms_batch 引用」409 约束；sync 覆盖已绑定厂商编号的 pending/approved/rejected 并返回 202。草稿态仅库表默认 / 历史数据，界面保留展示不新增入口。现有
  • 模板名称与内容属加密列（name_enc / content_enc），读取走既有受控解密与 template_content_read 审计；本页不涉及手机号，无掩码 / 解密边界问题（规则 2）。现有
