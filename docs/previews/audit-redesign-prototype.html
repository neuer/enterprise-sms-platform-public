    设计决策（相对现网的变更点）

  • el-card 外壳与 filter-grid 十二列栅格退役：七个筛选器收进方案 A 单行检索条——操作人关键词 220px + 动作下拉（选项来自 GET /admin/audit-logs/actions，可输入新值）+ 对象类型 + 对象 ID + 时间范围 datetimerange + 查询/重置；低频次精确字段「稳定账号 ID / 关联 ID」收进「更多筛选」气泡且激活带角标计数，与批次列表同语言。检索条并入 reply-* 共享组，filter-grid 全站随之退役。前端
  • 常驻规则条 slim 两格：不可变账本（append-only、七个运行角色均无 UPDATE/DELETE/TRUNCATE 权限、保留 36 个月由 DBA 变更单驱动清理）与 PII 边界（手机号、逐号密文与 HMAC 列表无法写入 audit_log，载荷只记数量与引用），与 user-rules 同组常驻。前端
  • 结果面板化并入 reply-results 共享组：撤下「操作事件流」卡头，列保持 稳定主体 / 操作人快照 / 动作 mono / 对象 / IP / 时间 mono / 详情；底栏合并「共 N 条 · 每页 20」+ 分页并入 reply-pagination 共享组，原 total>0 才渲染分页的限制退役；移动端 760px 表格↔卡片双渲染保留。前端
  • 详情抽屉保持载荷差异检视器：560 抽屉统一为 min(560px, 92vw)，描述格 + 关联 ID 复制/同链路追踪 + before/after 三列差异（变更琥珀 / 新增 verdi / 删除 verm / 不变淡化）+ PII 保护提示全部维持现状；「同链路事件」重查时自动展开更多筛选项气泡，如实展示激活的关联 ID 过滤。现有
  • 条底细字写明口径：操作人/动作/对象类型/对象 ID 与时间为服务端等值筛选，稳定账号 ID 与关联 ID（request ID）为精确匹配；筛选与分页均在服务端执行，不走「接口全量返回 · 前端过滤」。前端
  • 空态两行规约 + 错误条带重新加载：暂无审计事件（空库）/ 没有符合条件的审计事件（带清除筛选）；加载失败 el-alert 内联重新加载。全部既有 data-testid 与行为保留。现有

  • 列表 GET /api/v1/web/admin/audit-logs 参数 actor / actor_account_id / action / object_type / object_id / correlation_id / start / end / page / page_size 全部沿用；动作选项 GET .../audit-logs/actions 维持现状；零契约变更，不新增端点、不新增字段、不加导出。现有
