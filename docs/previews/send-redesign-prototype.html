为什么重构：现状问题清单（均对照 frontend/src/views/SendView.vue 与后端契约核实）

P0 · 正确性

  • 窗外转定时提交后才知道：deferred_reason 已在 preview 契约中声明，但服务端 build_billing_preview 恒返回 null，营销窗外提交前无任何提示。preview 实算

P1 · 体验断点

  • 文件导入无过程反馈：api 层 uploadPhones 已有轮询，但 :show-file-list="false" 下最长 120s 页面毫无动静；解析失败还丢弃服务端 error 原因，只给笼统文案。需要显式的 解析中 → 就绪/失败 状态机。端点已有，前端补状态机
  • 预检依赖手动点"更新预检"，表单变更后旧结果无 stale 标记，用户可能看着过期预检提交。防抖自动预检 + 过期标记
  • 用户看不到最终下发内容（签名前置 + 退订语自动追加后的完整文本），预检只有数字；退订语 suffix 文本在服务端 sys_config，前端无法自拼。preview 返回 final_content
  • 配额余量提交前不可见，超额只能等提交后 429。preview 返回部门配额摘要
  • 提交成功只有一行 alert：无批次号复制、无批次跳转、无"再发一批"重置，幂等命中淹没在长文本里。纯前端
  • 签名为自由文本输入，易写错格式（缺【】、未过审）。改已过审签名下拉，GET /web/signs 已有
  • 测试发送 ≤5 号码上限只在提交时被服务端拒绝，页面无联动校验。前端即时校验
  • 粘贴号码无实时统计（总数/去重/格式无效），剔除结果提交后才知道。前端实时统计

P2 · 表达

  • market 同意勾选挂在类别区，离其声明对象（本次发送的号码+内容整体）太远；移到提交前与审计说明同屏，语义更准。
  • 提交成功后按钮文案变成"已受理 · 写入审计"但表单未重置，状态语义混乱；改为显式结果卡。

方案概览

  • 方案 A · 确认式双栏（推荐）：保留现状左右分栏骨架，左栏只负责"填"，右栏 sticky 收敛为"确认区"——最终内容预览 → 受众与剔除 → 计费算式 → 配额条 → 风险合规行 → 同意勾选 → 提交。提交前一切需确认的信息在同一栏一屏内。
  • 方案 B · 三步向导：类别号码 → 内容签名 → 预检提交，每步校验门禁。对新操作员更友好，但牺牲密度、与平台"信息密度优先"立场相悖，作对照。
方案 A — 确认式双栏　FORM LEFT · CONFIRM RAIL RIGHT（推荐 · 主态：营销类需审批）

主态故意选信息最全的场景：营销类 + 粘贴 5,003 行 + 内容 86 字（2 计费段）+ 达审批阈值。右栏即"提交前确认单"：用户实收内容、剔除、计费、配额、合规风险、同意声明与提交动作纵向收敛。预检改为输入防抖 600ms 自动触发，下方所有数据同源一次 preview 调用。
