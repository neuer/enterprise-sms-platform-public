现状诊断（依据 2026-08-19 截图与当前 BatchView 代码）

  • 筛选区右上大面积空置：截图版本把测试发送 / 应用 / 部门平铺成 4 行，查询按钮垂直居中悬浮在右侧，右上约四成面积为空白。当前代码已把低频字段折进「更多筛选」气泡，但 flex-wrap 折行 + 按钮 margin-left:auto 的组合在折行时仍会在行尾留白；气泡下方还有一行 hint 小字吃掉高度。
  • 行高约 95px，首屏仅 5–6 行：批次号 32 位在列宽不足时折成 2 行，再加时间与徽标共 3 行；类别、内容、来源、构成数字、构成条各占一行；单元格上下 padding 12px。20 条/页需滚动 3–4 屏。

  • 表尾图例与分页分两行：构成图例一行、计数与分页又一行，再耗约 50px 垂直空间。

v2 改动清单（两个方案共用前四条）

  • 筛选条严格单行：批次号 / 类别 / 渠道 / 创建时间 + 更多筛选气泡 + 查询按钮，在 ≥1260px 内容宽内一行排下（当前内容区约 1300px）；去掉气泡下的 hint 小字，气泡激活时以角标计数提示。

  • 表尾合并：图例 + 计数 + 分页并为一行。
  • 方案分歧点：方案 A 保留「批次号完整 + 时间辅行」的双行结构（行高约 52px）；方案 B 压成单行扫表（行高约 36px），代价是批次号截断为 头8…尾4（点击复制全量）、时间精确到分。
