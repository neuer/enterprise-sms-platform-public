# docs/ui-design.md — 青鸾平台 UI 设计规范 v1.6

> 配套 `sms-ui-prototype.html`（关键业务屏静态原型）与 `frontend/tests/qingluan-*-contract.test.ts`（结构机判）。本文是视觉唯一基准，`frontend/src` 是唯一运行实现；冲突时先修正规范与实现，不得恢复第二套前端。

## 1. 设计立场

深色内部安全运营监视台：**信息密度优先、状态可读优先、克制的装饰**。深色不是装饰主题切换，而是青鸾唯一界面基准。全站记忆点是信道监视条（双队列深度 + QPS 令牌），发送页计费分段块与之呼应；系统机制直接成为界面语言。

## 2. 设计令牌（Design Tokens）

### 2.1 色彩

| Token | 值 | 用途 |
|---|---|---|
| --bg | #101814 | 页面底与工作区 |
| --panel / --panel-2 | #18231E / #141D19 | 卡片、表格与浮层 |
| --sink | #0C1512 | 输入框、深层容器与侧栏 |
| --tx / --tx-2 / --tx-3 / --tx-hi | #C9D2CC / #8B978F / #6D7A72 / #EAF1ED | 正文 / 次要 / 弱化 / 高强调 |
| --hair / --hair-2 | rgba(255,255,255,.08) / rgba(255,255,255,.05) | 控件边框 / 细分隔线 |
| **--verdi / --verdi-l** | **#0E7A63 / #2FA184** | **主色**：主按钮、选中态、success、verify 类 |
| --slate | #4574A3 | notice 类 |
| --amber | #D8A35C | market 类、warning |
| --verm | #E46A4F | danger、失败 |

Element Plus 映射以 `frontend/src/styles/theme.css` 为唯一实现：页面、浮层、输入、禁用态、遮罩和文字层级都必须映射到上述深色令牌；禁止组件回退到默认白色背景。根元素固定 `color-scheme: dark`。

**类别三色是硬约定**：verify=verdi、notice=slate、market=amber，出现在类别标签左竖条、统计分段条、图表系列色，任何页面不得混用其他色相表达类别。

### 2.2 字体

| 角色 | 字体栈 | 规则 |
|---|---|---|
| 界面/正文 | PingFang SC, HarmonyOS Sans SC, Source Han Sans SC, Microsoft YaHei, system-ui | 基准 13px/1.6；H1 19px/600；表格 12.5px |
| **数据字** | IBM Plex Mono, JetBrains Mono, Consolas, monospace | 批次号、customId、手机号、金额/条数/百分比、时间戳；一律 `font-variant-numeric: tabular-nums` |
| 品牌字 | Noto Serif SC, Source Han Serif SC, serif | 仅两处：侧栏「青鸾」logo、登录页大字。其余禁用衬线 |

### 2.3 形状与层次

圆角：卡片 10px / 控件 7px / 标签 5px。以 `hair` 细边框和 panel 层级代替大面积阴影；阴影只允许 Drawer 与 Popover。间距采用 4 基数。品牌印章允许 verdi 深浅渐变，普通按钮禁用装饰性渐变与大圆角胶囊。

## 3. 布局

216px 深墨侧栏（分组：概览/发送/治理/管理/运维，角色控制可见项）+ 56px 顶栏 + 内容区 max 1440px。<960px 时侧栏收起为抽屉；390px 必须无页面整体横向滚动。

**顶栏固定结构**：面包屑 ｜ 信道监视条 ｜ 余额 ｜ 用户。信道监视条数据来自 Prometheus 指标接口，10s 轮询；余额点击跳余额走势。

## 4. 核心组件规约

| 组件 | 规约 |
|---|---|
| `<CategoryTag>` | 左侧 3px 竖色条 + 类别名；三色见 2.1 |
| `<StatusTag>` | 状态→色：queued/sending/在途=info 灰；delivered/completed=verdi；failed/rejected=verm；pending_approval/scheduled=amber；balance_blocked/uncertain 使用更高对比的 danger 组合，表示“需要人来” |
| `<PhoneMask>` | mono 显示 `138****2041` + 眼睛图标；点击→调解密接口→行内替换明文并 toast「已记入审计」；无权限则图标隐藏 |
| `<SegmentBar>` | 计费分段可视化：满段实心 verdi 块、末段斜纹块（title 显示 n/67 字）、恒显 1 个灰色 ghost 块提示下一段边界；数据只来自 /billing 预估接口 |
| `<ChannelStrip>` | 顶栏签名组件：实时(verdi)/批量(amber)两条深度条 + 5 枚 QPS 令牌点（占用=verdi 实心） |
| 结果构成条 | 批次列表与 560 抽屉共用四段条（送达 verdi / 失败 verm / 待回执 slate / 未提交 tx-3）；列表 5px、抽屉 9px。明示占受理总数份额，不是成功率；禁止 donut |
| 表格 | 行高 40、th 11px 字距 0.08em、panel 背景与 hair 分隔；hover 只提高一层亮度；数字列右对齐 mono；行点击开 Drawer（560px），不整页跳转 |
| 空态 | 两行文案：一行结论粗体 + 一行"这里会出现什么/下一步"，不放插画 |

## 5. 文案基调

按钮写结果：「已充值，恢复队列」「通过并排期」「下载剔除清单」。错误讲原因和出路：「营销发送须先确认用户同意」。危险与留痕如实告知：「勾选行为与操作人将写入审计日志」。全站中文、句号收尾的长提示、不用感叹号。

## 6. 动效与可达性

仅三处过渡：Drawer 滑入 220ms、按钮 hover 120ms、switch 150ms；无入场动画、无环形加载堆叠。`prefers-reduced-motion` 全关。焦点样式 2px verdi 外描边全站保留；表格行可键盘 Enter 开 Drawer。

## 7. 页面基准（与原型逐屏对应）

1. **仪表盘**：分层总览。业务成果四卡（今日消息三色分段条 / 分类目成功率 / 待审批 2px 琥珀顶 / 余额预计可用；角链 → 报表/审批/余额）→ 近 7 日堆叠柱铺满中栏（图例在柱下，底下不留空）+ 厂商余额 64px sparkline 与四格（阈值 / 日均 / 预计可用 / 余额轮询，不画阈值虚线）→ 运行健康：方案 A 单行信道条（LIVE / 双队列 16px+6px 轨 / 5 枚 14px 令牌 / 最近更新）+ 告警 / 待处置三行 / 任务健康（大号 N/M + 仅异常项）。10s 轮询；H1 19px 无衬线。不得虚构「最早提交于」等接口没有的字段
1a. **统计报表**：方案 A 分析工作台。单行工具条（周期/维度胶囊 + 类别 + 范围 + 查询/导出明细 CSV + 含明文手机号勾选）→ 四卡 KPI（消息数含区间天数与日均/峰值 MM-DD、计费条、成功率拆解且标明 unknown 不入分母、结果构成条）→ 趋势堆叠柱约 170px（图例在柱下、Top 5 + 其他、消息数/计费条切换）+ 维度排行（轨色跟图表序列、不编造 slug）→ 明细八列（周期 / 维度 / 消息数 / 计费条 / 送达 / 失败 / 未知 / 成功率，分页 20）。导出条仅有任务时出现，铬为圆角 10 + 状态 tag +「下载 CSV ↓」。改筛选不自动重查，条下提示条件已变更。成功率只展示服务端口径。H1 19px 无衬线。不得虚构「长短信主要来自营销类模板」等接口没有的判读
2. **人工发送**：左表单（类别三选卡片 notice→market→verify、号码粘贴/导入+四类剔除摘要、模板+签名、定时勾选/测试开关）＋ 右侧 sticky 确认区（最终内容预览、受众与剔除、16px SegmentBar、`n×s` 消耗、配额条、风险合规、market 同意琥珀框、按钮文案随场景切换 立即发送/安排发送/提交审批）
3. **批次列表**：方案 A 账本工作台（v2 密度版）。独立单行 verdi 胶囊筛选条（批次号 / 类别 / 渠道 / 创建时间 datetimerange / 更多筛选折叠测试·应用·部门且激活带角标计数 + 查询/重置，改条件不自动重查）→ 状态分组 chips（进行中=queued+sending，计数来自 status_counts）→ 紧凑双行账本表（行高 ≈52px：批次号强制单行不折行，时间与定时/测试/重发徽记合并辅行；类别标签与内容摘要同一行；来源渠道·应用·部门单行；四段条 5px 送达/失败/待回执/未提交，明示非成功率；单元格 padding 7/10）→ 560 抽屉（操作显隐+原因、hero 四计数、sink 正文、松散事实格、号码明细）。页头口径绿点标签；页脚合并一行（构成图例 +「共 N 个批次 · 每页 20」+ 分页）。H1 19px 无衬线。类别继续左 3px 竖条。不得虚构退订语来源、成功率或方案 B 行内展开
3a. **号码搜索（v1.7 重构）**：检索条单行（手机号 mono + 时间范围 datetimerange + 列表/时间线 verdi 胶囊 + 查询），隐私说明沉条底；检索成功后号码徽标条双视图常驻（掩码/解密号码 mono + 黑名单 verm tag + 来源只映射 manual→人工加入 / reply_optout→回复退订 / import→导入 + 近30日接收量 mono + approver/admin「授权查看」一次解密一次审计，toast「已解密 · 本次授权查看已记入审计」）；列表去恒定号码列，类别左 3px 竖条 + 内容摘要（verify 已打码）+ 状态内联厂商回报，`sent` 仍叫「已提交」，类别/状态筛选收进结果区页脚「共 N 条 · 每页 20」；时间线按日分组（日期+星期+事件数，星期由 ts 前端换算）垂直细线串联，下行事件类别色圆点与竖条左对齐，用户回复右缩进 24px 前缀"↩ 用户回复"，truncated 琥珀条如实告知 500 条上限。H1 19px 无衬线。不得虚构退订日期、回复脚注「已入 /replies」或「已触发退订」、号码空格分组、本页「23/47」口径或方案 B
3b. **上行回复（v1.6.59）**：独立单行 verdi 胶囊检索条（手机号 mono + 回复时间 datetimerange + 处置全部/待加黑退订/已加黑 + 查询/重置，胶囊点选即重查，隐私说明沉底细字写明 phone_hmac 与无解密）；密表格（回复时间 mono / 掩码号码无解密入口 / 退订语 verm 高亮 / 关联批次可点击跳 /batches?batch_no= Drawer、未关联 amber tag 附「未匹配到平台批次」/ 状态列全角色可见 / 处置按钮仅 operator+admin）；底栏「共 N 条 · 每页 20」+ 分页。加黑确认如实告知剔除后果与审计留痕，toast「已加入退订黑名单 · 本次操作已记入审计」，成功后重查列表。空态两行规约分未采集/筛选无结果。H1 19px 无衬线。不加解密端点、不加导出（FR-07）。不得虚构批次类别/提交方副行、未关联「厂商未回传 customId」或号码空格分组
4. **审批中心**：方案 A 队列工作台。单行 verdi 胶囊筛选条（四态计数 + 类别/部门/申请人/排序 + 刷新/30s 自动）→ 临期队列（倒计时列 86px、行 padding 14×18、圆角 12、批次号 tx-hi、事实行 em 分隔且数字加粗，倒计时保持 HH:MM:SS + 1s tick）→ 560 抽屉（松散事实格 + sink 正文块 + 通过前去向预告，只依据 scheduled_at / 类别，不预判营销窗）→ 已办表去向列。页脚「共 N 条 · 每页 20 · 30s 轮询中 · 上次更新 HH:mm:ss」。H1 19px 无衬线。本人单只显示「本人提交 · 按规则回避」。不得虚构已剔除/近 7 天/窗外预判/当前配置阈值
5. **运维中心（重构）**：页头副文写明机制事实（恢复动作均有守卫与审计、原始报文只展示无 PII 元数据）+ 右侧「审计在线 · 安全元数据」状态徽标 → 熔断横幅卡（琥珀底 + 「已充值，恢复队列」主按钮，仅队列暂停或刚恢复时出现）→ 自定义页签条（告警记录 / 回调任务 / 原始报文 / uncertain / unmatched / 任务健康 / 队列恢复 / Outbox 投递，与 config-tabs 同组，横向溢出滚动，键盘左右切换，?tab= 深链与首访 lazy 渲染不变）→ 常驻规则条两格（守卫与审计：重放/手动触发/死信重推/队列恢复均二次确认并写审计、uncertain 只读仅 reconcile 可迁移禁止自动重发；PII 边界：原始报文只展示无 PII 元数据、手机号仅在内存转 HMAC、明文导出需二次认证）→ 各面板标题行 + 方案 A 单行检索条（告警=类型关键词 220px + 等级 seg 全部/info/warn/crit 点选即重查 + 时间范围 + 查询/重置；原始报文=来源 seg 全部/报告/回复 + 处理状态 seg 全部/待重放/已处理 点选即重查无查询按钮；unmatched=手机号 mono 250px + 报告时间 + 查询/重置 + 右侧导出区 授权明文勾选/导出对账；Outbox=状态 seg 全部+六态点选即重查；条底细字如实写明服务端分页过滤与隐私边界，不新增查询参数）→ 结果面板密表格（并入 reply-results 共享组，既有列与移动端双渲染保留；Outbox 保留六格统计 待投递/已发布/处理中/死信/失败尝试/最老积压）→ 页脚「共 N 条 · 每页 20」+ 分页（并入 reply-pagination 共享组；任务健康无分页，计数收进面板副题）。报文重放/手动触发/死信重推/队列恢复四处确认改 h() VNode 拆后果正文与审计细字（ops-confirm-dialog/ops-confirm-audit 并入 sign-* 共享组），恢复确认按 force 取值切换后果文案，成功 toast 统一带「本次操作已记入审计」。告警详情 440 抽屉、回调任务嵌入 CallbackView 紧凑工具栏、导出 step-up 密码流程与 loadToken 竞态防护维持现状。空态两行规约分空库/筛选无结果。H1 19px 无衬线。admin 专属；零契约变更；不得虚构全量统计计数、队列深度数字或厂商返回字段
